# Diagnostic Codes

Every diagnostic ShadowDusk emits carries a code. This page is the complete registry: look up the code you saw in your build output to find out what triggered it.

Two things worth knowing before you read the table:

- **Codes from the *underlying* compilers are passed through verbatim** and are not listed here. When DXC, `d3dcompiler_47`, or vkd3d-shader rejects your shader, you get that compiler's own words, unedited, along with the file, line, and column it reported. ShadowDusk never rewrites or summarizes a diagnostic it did not produce.
- **`SD0400`–`SD0499` are always warnings.** They flag constructs that compile successfully but are known to fail or silently misbehave at *runtime* on narrower OpenGL stacks (WebGL, ANGLE, strict Mesa drivers), where the engine's own error is a generic draw-time exception. They never reject a shader.
- **Some codes outside that range are warnings too**, marked **Warning** in the table: `SD0007` (a ShaderToy conversion adjustment), `SD0008` (an `#include` that only resolves because the file system ignores case), `SD0009` (the managed preprocessed view of the technique list could not be built, so the techniques are read from the raw source; its OpenGL sampler-register form is an error), `SD0017` (a global initializer ShadowDusk cannot evaluate, so that parameter's default would be zero), `SD0029` (CLI only: an `.xnb` requested with no profile, so it holds a `DirectX_11` effect), `SD0104` (an unrecognized vertex-input semantic defaulted to TextureCoordinate, exactly as `mgfxc` defaults and warns), `SD0214` (DirectX 12 DXIL compiled unsigned on a non-Windows host), `SD0220` and `SD0226` (build warnings raised in your own build when it resolves a Vortice.Dxc or Silk.NET SPIRV-Cross native other than the pinned one), `SD0222` (a DirectX 12 texture array, reflected as one parameter on the first slot exactly as `mgfxc` reflects it, with the other elements unreachable in the engine; a sampler array is the error `SD0224` instead, on DirectX 11 and 12, because `mgfxc` refuses it in its own parser), `SD0230` (DirectX 11: a shader's legacy-sampler texture slots could not be proven to match `mgfxc`'s, so the declaration-order slots are kept), `SD0235` (Vulkan: a texture sampled through a second sampler gets a second descriptor), `SD0614` (SkSL converter: a synthesized uniform your draw code must set) and `SD0637` (raylib converter: `sampler_state` entries raylib cannot carry). Like every warning, they never gate output.

To see everything wrong with a shader in one pass, including warnings and across several targets, call `ValidateAsync` instead of compiling. See the [In-Memory Quickstart](getting-started/in-memory-quickstart.md).
