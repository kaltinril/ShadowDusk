# Phase 70 appendix: reviewed manifest movement (DXC v1.7.2212 to v1.9.2607)

Every entry of `tests/fixtures/golden/byte-identity/dxc-targets-manifest.json` that moved, compared old pin against new pin. Generated from the DXC dumps of both pins (`SHADOWDUSK_BYTE_IDENTITY_DUMP`) and a real `mgfxc` 3.8.6.1 build of the corpus.

**How to read the class.** Code is compared after removing metadata, debug records and value numbering.

- *identity or metadata only*: every shader has the same instructions; the bytes moved because DXC's identity string, the validator version, debug metadata or the hash changed.
- *code moved, every mgfxc shader reproduced*: the instructions changed, and every shader of the real `mgfxc` 3.8.6.1 build of this fixture is reproduced exactly. These are the strongest entries.
- *code moved, partly reproduces mgfxc*: debug arms only. `mgfxc` was built without debug information, so its release shaders do not match debug ones.
- *code moved, no mgfxc reference*: `mgfxc` produced no shader for this fixture (it drops a shader its DXC rejects, for example legacy `sampler2D` / `tex2D` at SM6). Reviewed by opcode delta below; the render gates are the proof.

## What the code movement is

Read from the opcode deltas of the release entries below:

1. **Short-circuit control flow (HLSL 2021, DirectX 12 and Vulkan only).** `select` becomes `br` + `phi` where `&&`, `||` or `?:` now short-circuit. This is the change `mgfxc` makes too.
2. **One real semantic change, also from 2021: a side effect in a `?:` arm.** `examples/ExArrayTernaryAssign.fx` has `Thresholds[i] < x ? acc = w : acc`. At 2018 both arms ran, so `acc` always took `w` and the comparisons were dead code. At 2021 the assignment runs only when the condition holds, so the compare and select instructions appear. This is what the language means and what `mgfxc` 3.8.6.1 was measured to compile for the same construct on `DirectX_12` (a compare and a select per arm); OpenGL and DirectX 11 keep `fxc`'s behavior.
3. **`mad` lowering on SPIR-V.** DXC no longer fuses a multiply and an add into `Fma`: all 1096 `OpExtInst Fma` in the Vulkan dumps become `OpFMul` + `OpFAdd`/`OpFSub`. This accounts for most Vulkan arithmetic deltas and for the OpenGL GLSL deltas.
4. **LLVM and SPIRV-Tools canonicalization.** Reordered operands, `a + (-b)` to `a - b`, fewer redundant `fmul`/`fsub`, and per-component loads in place of a whole-vector load and extract.

**OpenGL (4 of 51) and Slang OpenGL (8 of 21).** OpenGL stays at HLSL 2018, so only items 3 and 4 apply. The GLSL of the four moved fixtures (`Dots`, `Fading`, `HalfGlobals`, `MultiTextureOverlay`) was read old against new, every changed line. Each is the same arithmetic rewritten: `x * 2.0 + (-0.4)` to `(x * 2.0) - 0.4`, `a + (-b)` to `a - b`, the operands of an addition swapped, and `((1 - a) * (-2)) * (1 - b) + 1` to `1 - ((2 * (1 - a)) * (1 - b))`, plus renumbered temporaries.

**One refusal's text changed:** `third-party/KNI/DeferredBasicEffect.fx` on Vulkan still fails on `COLOR0` with the same diagnostics, and DXC now also lists two `Initializer of external global will be ignored` warnings.
