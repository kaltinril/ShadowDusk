## 1. Critical

### C1. Rule 13 loop rewrite drops the finalizer for `<=` loops (the issue-#160 bug, one operator over)
`src/ShadowDusk.GLSL/MonoGameGlslRewriter.cs:3098` (pattern `:3288`, tail regex `:2963`)
`TryParseSoleIfElse` accepts all four comparisons (`<=|>=|<|>`) and the tail regex accepts
`++`, `--`, and any `OP=` step, but the emitted header is hard-coded `for (…; idx <= provenMax; …)`,
which is only correct for `<` with a monotonically increasing index:
- Inner `if (idx <= bound)` (from HLSL `for (i = 0; i <= n; i++)`): the index can never reach
  `bound + 1`, so the `else` finalizer that initializes the loop's phi output is unreachable —
  the value is read uninitialized. Silent wrong pixels on every GL target. This is exactly the
  #160 failure mode reintroduced for inclusive bounds. Fires whenever the runtime bound equals
  the proven max (always, for bare-literal bounds).
- A bare negative literal bound: header `idx <= -1` never runs, skipping a finalizer the
  original executed once.
- Descending shapes (`>`/`>=` with `--`, both accepted by the patterns) would emit
  `for (int i = 8; i <= 0; i--)` — zero iterations, the whole loop erased.
Every Rule-13 unit test pins only `if (_x < _y)`; no `<=`, negative, or descending case exists.
**Fix direction:** restrict `IfConditionPattern` to `<` and the tail to `++`/`+= 1` (decline the
rest to the honest SD0402 path), or emit `<= provenMax + 1` for `<=`. Add tests for all four
operators. Verified line-by-line.

### C2. FX pre-parser parses `#if`-disabled techniques as live (phantom techniques, false duplicates)
`src/ShadowDusk.HLSL/FxPreParser.cs:1560` + `src/ShadowDusk.Compiler/Internal/CompilationPipeline.cs:87-94`
Stage 1 (FxPreParser) runs on raw source and `SkipNonCodeTokens` treats every
`#if/#else/#endif` as trivia, so both branches are live to the technique parser. Consequences:
- `#if OPENGL technique T {…} #else technique T {…} #endif` → false FX0005 "Duplicate technique".
- `#ifdef HIGH_QUALITY technique Fancy {…} #endif` (undefined) → `Fancy` silently compiled into
  the `.mgfx`, shifting technique indices vs mgfxc — silent wrong output.
- Hard-error checks (FX0012/FX0013) fire on dead branches.
Also, `#include` flattening happens *after* the pre-parse (`CompilationPipeline.cs:116`), so a
technique in an included file is invisible at Stage 1 → misleading SD0010 on OpenGL for a valid
mgfxc effect (the zero-technique DXC recovery is gated to SM4/SM6 macro sets); with a second
technique in the entry file, the include's raw technique text leaks into the DXC input.
**Root cause:** the input AST has no notion of preprocessor-conditional structure. The clean fix
is running the technique-relevant part of preprocessing (conditionals + includes) before the
pre-parse, mirroring mgfxc's preprocess-then-parse order. Verified.

### C3. macOS single-file CLI archives cannot load their own bundled natives (CI-masked)
`src/ShadowDusk.HLSL/Dxc/DxcLoader.cs:123-132`, `src/ShadowDusk.HLSL/Vkd3d/Vkd3dLoader.cs:94`,
`src/ShadowDusk.HLSL/ShadowDusk.HLSL.csproj:89/93/109/113`, `.github/workflows/release.yml:457-458,493`
The mac dylibs are `Link`ed into per-arch subdirs (`osx-arm64\libdxcompiler.dylib` — required,
both arches share one file name), the release publish embeds them
(`IncludeNativeLibrariesForSelfExtract=true`), and single-file extraction preserves those
relative subdirs. But: probe step 1 checks per-arch subdirs only under `AppContext.BaseDirectory`
(the apphost dir, where nothing is on disk); steps 2–3 probe the extraction dir **flat only**.
Nothing ever probes `<extractionDir>/osx-{arch}/`. An end user running the released
`shadowdusk-osx-*.tar.gz` outside a repo checkout gets `DllNotFoundException`/failed compile for
every shader. The release smoke (`release.yml:493`) runs from the CI checkout, where the
walk-up probe finds restored `tools/dxc|vkd3d/` — permanently masking the break. Windows/Linux
are unaffected (their natives are linked flat); the NuGet library and dotnet-tool shapes are
unaffected. Violates Core Design Constraint 7 for the mac archives.
**Fix direction:** also probe `Path.Combine(dir, rid, fileName)` in the
NATIVE_DLL_SEARCH_DIRECTORIES loop of both loaders (the extraction dir is in that list), and
make the smoke `cd "$RUNNER_TEMP"` before running so CI can actually see this class. Chain
verified end-to-end (loader, csproj, workflow); final behavior rests on standard .NET 8
single-file extraction semantics — reproduce once on a real mac to confirm.

### C4. WASM host misses `RelaxNanChecks` — issue #149 (macOS isnan) still alive in the browser
`src/ShadowDusk.Wasm/JsShaderBackends.cs:151-157` vs `src/ShadowDusk.GLSL/SpirvCrossGlslTranspiler.cs:120`,
`src/ShadowDusk.Wasm/wwwroot/shadowdusk-spirv-cross.js:142-152`
The desktop transpiler sets `RelaxNanChecks=true` (the #149 fix). The JS shim sets only the
other five options — no constant for `0x100004E` exists in the file — despite the comment
"Option values MUST match SpirvCrossGlslTranspiler exactly". Any shader using min/max/clamp
compiled in-browser gets the `isnan()`-ternary in versionless GLSL (the exact #149 load
failure), and browser bytes diverge from desktop bytes — breaking both determinism and the
one-pipeline rule. Three independent sweeps converged on this. Verified.

## 2. Major — silent wrong render

### M1. GL sampler record name vs GLSL declaration name can disagree (explicit registers)
`src/ShadowDusk.Compiler/Internal/CompilationPipeline.cs:741,763` vs `src/ShadowDusk.GLSL/MonoGameGlslRewriter.cs:376-377`
The `.mgfx` sampler record is named `ps_s{BindSlot}` from reflection (raw HLSL register), while
the rewriter renames GLSL samplers by declaration order (`ps_s{samplers.Count}`). Modern-syntax
`SamplerState s : register(s3);` → record says `ps_s3`, GLSL declares `ps_s0` → MonoGame's GL
uniform lookup misses (−1), the texture binds to unit 3 while the shader's sampler stays on
unit 0 — silently samples the wrong/stale texture. Additionally, the managed `SpirvReflector`
compacts slots while the DXIL oracle reports raw BindPoints, so desktop and WASM `.mgfx` bytes
diverge for sparse registers. No cross-validation exists between the two naming schemes. Verified.

### M2. Struct cbuffer parameters are written hollow — members dropped on every MGFX target
`src/ShadowDusk.Compiler/Internal/CompilationPipeline.cs:1991`, `src/ShadowDusk.HLSL/Reflection/ParameterListBuilder.cs`
All three reflectors extract struct members, but `ParameterReflection` has no `Members` field
and `BuildEffectParameterInfoList` hardcodes `Members: Array.Empty<EffectParameterInfo>()`. The
`.mgfx` loads (Struct/Void reads no data blob), but `Effect.Parameters["MyLight"].StructureMembers`
is empty — the parameter can never be set; its cbuffer region stays zero; render silently
diverges from the mgfxc build. FNA rejects structs loudly; MGFX paths have no guard. Verified.

### M3. GL rewriter semantic recognition is case-sensitive; unknown semantics pass through silently
`src/ShadowDusk.GLSL/MonoGameGlslRewriter.cs:1432,1443-1458`
`IsPositionSemantic` / `SemanticToVaryingName` / `SemanticToVertexUsage` compare ordinally
(`"POSITION"`, `"COLOR0"`, `StartsWith("TEXCOORD")`), but HLSL semantics are case-insensitive
and DXC mirrors the author's spelling — the same fact the SV_Target regex at `:169-173`
explicitly handles with `IgnoreCase`. A VS output `: Position` becomes `varying var_Position`
instead of `gl_Position`; `InjectPosFixup` finds nothing; compile exits 0; geometry renders as
garbage/nothing. Mixed-case VS/PS spellings also produce link-time varying mismatches. The
fallback comment says "won't occur in our corpus" — the corpus is not the input space. Verified.

### M4. Systemic: SPIRV-Cross emits GLSL 1.40, only eight lowerings exist, everything else ships silently
`src/ShadowDusk.GLSL/SpirvCrossGlslTranspiler.cs:97` (GlslVersion 140), rewriter rule roster, `GlslPortabilityAnalyzer`
The rewriter strips `#version` and lowers exactly: round/roundEven, trunc, one-shot do-while,
pow-square, reciprocal-quotient, and the three loop shapes. Everything else 1.30+/ES-3.00-only
that DXC+SPIRV-Cross legally emit from valid HLSL ships un-lowered and un-diagnosed into the
versionless dialect: `transpose` (the BuildUploadedMat4 comment itself admits it doesn't exist
in the target dialects), `sinh/cosh/tanh`, direct `isnan`/`isinf` (user-written — #149's fix
only suppresses the SPIRV-Cross-synthesized form), `texelFetch` (Texture2D.Load),
`textureSize` (GetDimensions), `floatBitsToInt`/`asuint` family, `switch` statements, integer
`%` and bitwise/shift ops, `uint` types/literals, `mat3(mat4)` constructors (the ubiquitous
normal-matrix cast), non-square matrix locals. The portability analyzer checks exactly three
things (SD0400/0401/0402) — nothing about builtins, operators, types, or statements. Issues
#107/#136/#138/#140/#149/#163 are this one gap discovered one construct at a time; the next
escapes are already enumerable. **Fix direction:** an analyzer pass over the final GLSL that
flags every 1.30+ construct without a lowering (loud SD04xx), plus lowerings for the common
ones (transpose, mat3(mat4), isnan). Mechanism verified; per-construct reachability is
standard DXC/SPIRV-Cross behavior.

### M5. Vulkan: two textures sharing one sampler silently co-locate — second texture unbound
`src/ShadowDusk.Compiler/Internal/VulkanTextureSamplerBindingRewriter.cs:148-153`
Self-documented: "two textures sharing ONE sampler within a SINGLE branch also land on one
index, leaving the second texture unbound … rather than … the silent co-location it gets
today." Classic diffuse+lightmap-with-one-sampler renders wrong on DesktopVK while GL/DX are
correct, with no diagnostic. Needs its own handling or a loud SD-code. Verified (in-code).

### M6. Vulkan/WASM reflection assigns dense slots that diverge from sparse explicit registers
`src/ShadowDusk.Core/Reflection/Spirv/SpirvReflectionParser.cs:159-178` vs `DxilReflectionExtractor.cs:247`
The SPIR-V parser buckets resources by class and numbers them 0-based in raw-binding order —
which equals the oracle's BindPoint only for contiguous-from-0 registers. `register(t1)` with
no `t0` → parser says slot 0, oracle says 1. On Vulkan (always SPIR-V-reflected) the `.mgfx`
slot masks disagree with MGVK's `binding − 32` slot math → texture lands in `Textures[0]`,
shader reads slot 1 → wrong/black texture. Also makes WASM (SPIR-V-reflected) OpenGL output
diverge from desktop (DXIL-oracle) output. Verified divergence mechanism.

### M7. DX12 compiles on Linux/macOS ship unsigned DXIL
`src/ShadowDusk.HLSL/Dxc/DxcShaderCompiler.cs:30-31`
"Load dxil.dll for DXIL validation on Windows; no-op on other platforms" — and macOS has no
dxil at all. A DX12-target `.mgfx` compiled on a Linux build box carries an unsigned DXIL blob
that retail D3D12 rejects at PSO creation, while the same source compiled on Windows works —
per-host output divergence for the same compiler version, against the one-faithful-pipeline
promise. Needs either cross-platform signing (dxil is now open-source), a loud diagnostic on
non-Windows DX12 compiles, or documented scope. Verified comment; runtime consequence is
standard D3D12 behavior.

### M8. Vulkan non-square matrix reflection ignores stride decorations
`src/ShadowDusk.Core/Reflection/Spirv/SpirvReflectionParser.cs:335-340` (decorations written at 651-657, never read)
Rows/Columns come from the SPIR-V matrix shape (DXC transposes HLSL matrix shapes) and size is
computed fully-packed `4*R*C` instead of stride-based DX layout. Non-square matrices on Vulkan
get transposed row/col counts vs the DXIL-oracle path and (for trailing small matrices) an
under-reported cbuffer `SizeInBytes`. Verified that `_memberMatrixStride`/`_memberColMajor`
are write-only.

## 3. Major — broken load, broken parity, silent drops

### M9. mgfxc's `/Defines:` flag is silently swallowed by the CLI
`src/ShadowDusk.Cli/ArgumentParser.cs:198-202` (and the comment at `:314-316` calling it a "future" flag)
MGCB's EffectProcessor passes `/Defines:NAME=1`; ShadowDusk's unknown-flag policy drops it —
no `CliArguments` field, nothing reaches the preprocessor. `#ifdef` branches silently compile
out with exit 0: silent wrong output plus a drop-in-parity break. Two sweeps converged. Verified.

### M10. DX12 vertex attribute table includes system values (SV_VertexID/SV_InstanceID)
`src/ShadowDusk.HLSL/Reflection/DxilVertexInputReflector.cs:36-46`
The DXIL input signature is consumed with no system-value filter, so `SV_VertexID` maps via the
unknown-semantic fallback to TEXCOORD0 — a phantom vertex attribute MonoGame then demands from
the vertex declaration (or collides with a real TEXCOORD0). The SPIR-V path correctly skips
builtins (`SpirvReflectionParser.cs:699-700`); the DXIL path doesn't.

### M11. Vertex-attribute reflection failures are swallowed into an empty table
`src/ShadowDusk.Core/Reflection/SpirvVertexInputReflector.cs:50-53`, `DxilVertexInputReflector.cs:31-33`
`catch (Exception) → Array.Empty` / `IsFailure → Array.Empty` (dropping `result.Error`). The
class's own remarks document the consequence: a zero-element input layout that fails
`CreateGraphicsPipelineState` with opaque `E_INVALIDARG` at the consumer's first Draw — the
exact Phase-54 crash class, and the exact issue-#141 silent-degradation pattern. A reflection
*failure* must be a compile-time error; only genuinely-input-free shaders may return empty. Verified.

### M12. Windows-style `#include` paths (and case mismatches) break on Unix hosts
`src/ShadowDusk.Core/Preprocessor/FileSystemIncludeResolver.cs:23,32`
The raw include capture is combined verbatim: `#include "Shared\Macros.fxh"` (common in
XNA-era trees) becomes a literal-backslash filename on Linux/macOS → SD0001 IncludeNotFound
for a file mgfxc compiles. Linux case-mismatch likewise. The sibling `InMemoryIncludeResolver`
normalizes separators; the disk resolver is the only one that doesn't. Verified.

### M13. GL stage-I/O declaration regexes cover only unqualified float/vec2/3/4
`src/ShadowDusk.GLSL/MonoGameGlslRewriter.cs:157-173`
`flat in vec4` (HLSL `nointerpolation`), `in`/`out` of int/uint/mat types, and non-vec4
SV_Target shapes fall through verbatim — modern `in/out/flat` syntax inside the versionless
artifact, un-renamed `in_var_*` body uses → Effect-load/link failure or garbage, compile exit 0.
Everything else unmodeled in this file fails loudly; these fall through silently. Verified regexes.

### M14. FX parser rejects or garbles legal fxc/mgfxc constructs (drop-in parity)
`src/ShadowDusk.HLSL/FxPreParser.cs` + `src/ShadowDusk.Core/RenderStateParser.cs:387`
Confirmed set:
- `VertexShader = NULL;` → FX0001 (`:1070`); `compile ps_2_0 PS(true)` args → FX0001.
- `AlphaBlendEnable = 1;` / `= (someBool);` / `= .5` → SD0011/FX0001; bools accept only
  True/False where mgfxc's ParseTreeTools also accepts 1/0; SD0011 additionally carries
  `File:"" Line:0` because pass-state spans are discarded (`CompilationPipeline.cs:602-604`).
- Annotations after an array suffix or `: register()` clause don't match the `Ident Ident <`
  strip gate (`:712-727`) → the FX-only `< … >` block leaks into DXC input → opaque DXC error.
  With a semantic present, the annotation attaches to the *semantic* name and silently never
  joins its parameter (`:730-749`).
- Annotation values must be a single token — `{1,1}` / `float4(0,0,0,1)` rejected (`:1452`).
- `Texture = NULL;` in sampler_state → texture literally named "NULL" → `NULL.Sample(...)` in
  rewritten HLSL (`:1313`).
- `technique10` unrecognized (only `technique`/`technique11`, `:445-447`) → body leaks to DXC.
- StencilRef/Mask reject hex (`0xFF`).

### M15. Nonzero annotation count can NRE consumers' games
`src/ShadowDusk.Core/MgfxWriter.cs:439` (+ KnifxWriter equivalent)
`WriteAnnotations` writes the real count while its own comment documents MonoGame reads the
count and materializes that many null slots, and mgfxc always writes 0. Game code touching
`.Annotations` NREs on ShadowDusk output where mgfxc output returns empty. Write 0 (drop the
count with the bodies) unless/until annotations are really shipped. Verified.

### M16. ShaderToy front-end maps `uint` to signed `int` with shifts passed through
`src/ShadowDusk.ShaderToy/TypeTable.cs:19`, `HlslEmitter.cs:733`
After a high-bit multiply, `h >> 15` sign-extends in HLSL (GLSL zero-fills) and `float(h)` goes
negative — hash/PRNG-based ShaderToys (a huge share of the corpus) silently produce different
noise. The "signed reinterpretation is behaviorally equivalent" comment is false for `>>` and
float conversion. Also: vector `==`/`!=` is scalarized only in `EmitCondition` (if/while/ternary)
— assignments, returns, args, and `for`-conditions emit raw vector comparisons (`HlslEmitter.cs:704,420`).

### M17. Library error-contract breaches: unguarded include read; watchdog cannot interrupt native hangs
`src/ShadowDusk.Core/Preprocessor/FileSystemIncludeResolver.cs:27`, `src/ShadowDusk.Compiler/EffectCompiler.cs:95`
- `File.ReadAllText` behind a TOCTOU `File.Exists`: a locked/ACL-denied include escapes as a raw
  IOException from `CompileAsync` (Result contract breach) and lands in the CLI as X0099 with
  the failing path lost. `PipelineRunner` maps this exact pair to X0001 for the main source only.
- `CompileAsync` is `Task.Run` over a sync core; cancellation is observed only at managed stage
  boundaries, so the documented 5-minute X0007 watchdog cannot interrupt a wedged native
  compile — MGCB hangs forever on the (rare, but documented-in-repo) native-pathology class.

## 6. The four questions, answered

**Are the ASTs (input / intermediate / output) complete?**
- *Input (FxParseResult):* good for the MonoGame-template subset (dual-branch defines,
  TECHNIQUE macros, 4 sampler_state forms, hex/negative values, ColorWriteEnable masks; the
  #106 class is genuinely hardened with strong tests). Structurally missing: preprocessor
  conditionals (root of C2), `technique10`, FX10/11 pass statements (SetVertexShader/
  SetBlendState), `VertexShader = NULL`, compile-args, expression/parenthesized state values,
  indexed stage states (`Sampler[0]`), sampler arrays, `string`/stateblock variables,
  GS/HS/DS pass slots, annotations on decorated declarators, non-scalar annotation values.
- *Intermediate:* mirrors MonoGame's Effect reader faithfully (field widths, enum ordinals,
  state defaults, alphabetical order, recursion — all re-verified against MonoGame 3.8.2).
  Missing: struct **members** (M2 — the one silent hole), GL vertex-usage coverage beyond
  POSITION/COLOR/TEXCOORD/NORMAL (N6 — loud), PSIZE (N5).
- *Output writers:* MGFX v10 / KNIFX / FNA layouts verified correct with real overflow guards
  (SD0020-23) and clean determinism (content-hash keys, invariant formatting, ordered
  iteration). One quirk: the annotation count (M15).

**Are we missing anything?** The single biggest systemic gap is M4: the GL output "AST" is
whatever SPIRV-Cross's GLSL 1.40 emitter produces, minus exactly eight lowerings, shipped
versionless with a three-check analyzer. Every recent Mac/Apos bug (#136-#163) is one instance
of that gap. Second: the input model's blindness to preprocessor structure (C2). Third: the
delivery-shape drift — WASM (C4, M6, N16) and the mac single-file CLI (C3) have quietly fallen
behind the desktop pipeline they're contractually equal to.

**Do we correctly convert between inputs and outputs?** The proven corpus converts correctly
(the rung-4 gates are real, and the sweeps re-derived the mat-transpose/mul scheme, uniform
naming, posFixup, FNA enum maps, and DXBC/DXIL container layouts as sound). Outside the corpus:
C1 (loops), M1/M6 (sampler slots), M2 (structs), M3 (semantic case), M5 (shared samplers),
M7 (DXIL signing), M8 (non-square matrices), M16 (ShaderToy uint) are all conversions that go
wrong *silently*. The pattern: each pipeline stage is correct for the shapes the corpus
exercises and unguarded one shape beyond it.

**Do we have valid exceptions for whatever scenarios?** Core discipline is genuinely strong:
zero sync-over-async, all native return codes checked, correct try/finally lifetimes, verbatim
diagnostics with line/column surviving the DXC/fxc hops, rewriter declines → loud
SD0210/SD0402. The breaches cluster in one habit — best-effort fallbacks that keep compiling:
M11 (empty attribute table), N5 (silent semantic default — now the `SD0104` warning),
N11 (parameter 0 coercion),
N16 (dropped WASM warnings), M17 (raw include throw), N9 (vkd3d line/col lost), N12/N13/N14
(CLI edges). Every one of those chooses "return something" over "surface the error" — the
issue-#141 failure mode the project says it internalized.
